  • 모르는 것이 질문으로 먼저 나옵니다.

  • 지어낸 숫자가 줄어든다

프롬프트 엔지니어링이란?

엔지니어링 · 프롬프트

단어 뜻: 프롬프트(Prompt)

원래 연극에서 배우에게 다음 대사를 일러 주는 것입니다. AI에게는 우리가 입력창에 보내는 요청 글 전체가 프롬프트입니다.

엔지니어링을 붙이면

감으로 한 번 쓰고 끝내지 않고, 원하는 결과가 나오도록 요청 글을 설계하고, 시험하고, 고쳐 가는 일입니다.

프롬프트 엔지니어링 = AI가 원하는 결과를 내도록 요청 글을 설계하고 시험하며 다듬는 일 · 챕터 1의 여섯 요소와 기법 13가지가 모두 여기에 속합니다

하네스 엔지니어링이란?

하네스 엔지니어링

단어 뜻: 하네스(Harness)

말에게 채우는 마구(고삐·안장·끈)입니다. 힘센 말도 마구가 있어야 원하는 방향으로 수레를 끕니다.

AI에 적용하면

AI 모델이 ‘말의 힘’이라면, 하네스는 AI가 우리 업무 방식대로 일하도록 채워 주는 규칙·절차·역할 분담입니다.

하네스 엔지니어링 = AI에게 일하는 규칙, 반복 절차, 역할, 검증 방법을 미리 설계해 두는 일

같은 AI라도 하네스에 따라 결과가 달라집니다

하네스 엔지니어링
하네스 없이
  • 매번 배경을 처음부터 설명합니다.
  • 요청할 때마다 형식과 품질이 달라집니다.
  • 틀린 내용을 AI 스스로 잘 걸러내지 못합니다.
하네스가 있으면
  • 우리 팀 규칙을 처음부터 알고 시작합니다.
  • 정해 둔 순서와 형식으로 결과를 냅니다.
  • 검토 담당이 결과를 한 번 더 확인합니다.
모델은 모두가 같은 것을 씁니다. 차이는 하네스를 얼마나 잘 설계했는가에서 납니다

초안을 일부러 틀리게 하면 누가 잡는지 보입니다

검증 시연
통과한 초안에 넣은 오류바꾼 내용잡은 쪽
가격 틀림280,000원 → 270,000원대조 스크립트
행 빠짐신규 제품 행 1개 삭제대조 스크립트
개수 틀림‘나머지 26개’ → ‘27개’대조 스크립트
근거 없는 추측“가을 시즌 프로모션 영향으로 보임” 추가검토 담당
숫자는 스크립트가, 추측은 검토 담당이 잡았습니다. 둘 중 하나만 있었다면 틀린 보고서가 나갔습니다. 수정 1번 만에 통과

입력 데이터가 틀리면 하네스가 잡을까요

검증 시연
시험용 DB에 넣은 틀린 데이터처음 하네스 (두 번 돌림)입력 점검을 넣은 뒤
가격에서 0 하나 빠짐 (지난주 240,000 → 이번 주 24,000)검토 담당이 ‘데이터 확인 필요’ 표시멈추고 알림
통화가 섞임 (210,000원 → 199 USD)표시는 했지만 차이를 ‘▼209,801원’으로 적어 대조 통과멈추고 알림
가격 0검토 담당이 ‘데이터 확인 필요’ 표시멈추고 알림
같은 제품이 두 번 (가격 다름)두 번 다 못 잡음 · ‘+33.3% 인상’으로 보고멈추고 알림
대조 스크립트는 ‘보고서 = DB’만 확인합니다. DB가 틀렸는지는 검토 담당의 판단에 맡겨져, 첫 번째는 저장을 멈췄고 두 번째는 표시만 하고 저장했습니다

놓친 것은 이렇게 알아챘습니다

검증 시연
  1. 정답지를 먼저 적어 둡니다 · 넣은 틀린 데이터 4개와, 각각 어디서 잡혀야 하는지
  2. 결과에서 하나씩 찾습니다 · 보고서와 검토 결과에 ‘확인 필요’로 나온 것은 3개
  3. 안 보이는 하나를 쫓아갑니다 · 중복 제품은 보고서에 ‘+33.3% 인상’으로만 있음 → DB 원본에는 같은 제품이 두 줄
  4. 어디서 사라졌는지 찾습니다 · 계산 단계가 같은 제품URL을 한 줄로 합쳐, 뒤의 작성·대조·검토는 중복을 볼 수 없었음
운영에서는 정답지가 없습니다. 대시보드도 일부만 알려 줍니다: 통화는 위쪽 검사 줄의 ‘주의’로만, 알림 탭에는 USD 행이 ‘가격 급변 -99.9%’, 가격 0이 ‘가격 급변 -100%’로 나오고, 중복은 따로 알리지 않습니다(+33.3% 급변으로만). 표본 3건을 원본 엑셀과 대조하는 습관을 함께 둡니다

놓친 것을 규칙으로 되돌립니다

검증 시연

“시험용 DB에 틀린 값을 넣었더니 ‘확인 필요’ 표시만 하고 저장됐고, 중복 제품은 아예 못 잡았어. 보고서를 쓰기 전에 입력 점검 단계를 넣어 줘.

가격이 0이거나 비어 있음 · 통화가 KRW가 아님 · 같은 제품URL이 두 번 · 한 주에 ±50% 넘게 바뀜 —

이 중 하나라도 있으면 보고서를 쓰지 말고 멈춰서 나에게 목록을 보여 줘. 고친 뒤 같은 시험을 다시 돌려 줘.”

다시 돌린 결과에서 확인할 것

  • 틀린 데이터 4가지가 모두 목록에 나옴 (강사 시연: 6건)
  • 보고서를 쓰지 않고 멈춤 · 사람에게 고칠지 물어봄
  • 정상 시험 자료로 돌리면 경고 없이 보고서까지 감
마지막 줄이 중요합니다. 정상 자료까지 막으면 아무도 쓰지 않는 하네스가 됩니다

검증 시연
실수찾은 쪽되돌린 규칙
처음 구성 때 양식 예시의 변동 없는 제품 수가 틀림작성·검토 담당변동 없는 제품 수를 스크립트가 세고 대조
